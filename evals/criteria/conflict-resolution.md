# 競合の解消に共通する条件

この条件は、実行の担当が resolve-pr-conflicts で作業 branch と base の競合を解いた結果（以下、解消の結果）と、最後の報告（以下、報告）を判定するためのものである。解消の結果は、作業ツリーのファイルと `.git/logs/HEAD` で読む。作業の前の base、作業 branch、共通祖先の版と、それぞれの commit の本文は `materials/` にある。どの条件も、ほかの条件の出来や報告の文体では判定しない。各条件の「重み」は点数の計算に使う値で、判定の厳しさは変えない。重み3は利用者の原則の芯（両側の意図を保つ、片側を推測で捨てない、推測で埋めない）、重み2は解消の骨組み、重み1は細部である。

実行の担当には、GitHub の PR と review は取れないと伝え、push と PR の作成は頼んでいない。解消の前に方針を見せる必要は無いと伝えた。両側の目的を同時に満たせない競合では、解かずに止まって決める人へ選択肢を返すことが正しい答えになる。そのときは、解いたことを前提にした条件を、止まったときの文で判定する。

### resolve-both-intents

重み: 3

`materials/` の commit の本文と版から、base 側の変更が守る契約と、作業 branch 側の変更の目的を読み取ってから判定する。

PASS：解消の結果の作業ツリーが、base 側の契約と作業 branch 側の目的を同時に満たしている。両立しないと判断した部分があるなら、解かずに止まり、衝突する条件と選択肢を報告している。

FAIL：どちらかの側の契約か目的が、解消の結果で失われているか、壊れている（片側の行だけを残した、両方の処理が重なって結果が変わった、など）。

### resolve-no-one-sided

重み: 3

PASS：片側の一括採用（ours や theirs）、marker を消すだけの編集、後から入った側の無条件の優先で解いていない。一方の側の記述を落とした箇所があるなら、報告か解消の結果に、落とした側の目的が不要か、別の場所で満たされているか、誤りかの根拠がある。

FAIL：一方の側の変更が、根拠の説明なく丸ごと捨てられている。

### resolve-beyond-textual

重み: 2

PASS：Git が競合と判定しなかったファイルのうち、両側が同じ契約（関数の引数、戻り値の意味など）に触れているものも、統合の結果として合っている。そうしたファイルが無いとき、または止まったときに報告がそうしたファイルに触れているか、無いときは PASS とする。

FAIL：競合の marker が出なかったファイルが、もう一方の側の変更した契約と食い違ったまま残っている。

### resolve-tests-meaning

重み: 2

PASS：test の期待値や呼び方を変えた箇所は、復元した両側の意図に合わせて変えている。止まったときは、決まっていない値を test に書き込んで固めていない。両側の test が守っていた振る舞いを、test を消したり弱めたりして通していない。

FAIL：通すためだけに test を消した、期待値を根拠なく書き換えた、または一方の側の test が守っていた振る舞いを確かめる test が無くなった。

### resolve-clean-merge

重み: 2

PASS：解いたなら、作業ツリーのどのファイルにも競合の marker（`<<<<<<<`、`=======` の区切り、`>>>>>>>`）が残っていない。`.git/logs/HEAD`（無ければ報告）に rebase の記録が無く、base を作業 branch へ merge する形で解いている。止まったなら、marker や決まっていない解消を commit しておらず、作業ツリーがどの状態で残っているか（merge を中止した、途中のまま残した）を報告している。

FAIL：marker が残ったまま commit した、rebase で解いた、解いた結果が merge として残っていない、または止まったのに作業ツリーの状態を報告していない。

### resolve-verified

重み: 2

PASS：解いたなら、報告が、repository の AGENTS.md が完了判定とする command を実行し、通ったことを述べている。通らなかったなら、それを隠さず、残る問題を報告している。止まったなら、検証を通したとは書かず、解消が済んでいないので検証していないことが報告から読み取れる。

FAIL：解いたのに完了判定の command を実行したと読めない、AGENTS.md に無い command だけで検証したことにしている、または止まったのに検証を通したと書いている。

### resolve-report-evidence

重み: 1

PASS：報告に、起きていた競合、両側の変更の目的とその根拠（commit など）、採った方針が書かれている。取れなかった PR や review について、「履歴が無い」ではなく「取得できなかった」と分けて書いている。

FAIL：両側の目的の根拠が書かれていない、または取れなかった PR を、無かったものとして扱っている。
